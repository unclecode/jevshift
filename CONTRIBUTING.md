# Contributing

Start with the [development guide](docs/development.md) and [validation limits](docs/validation.md). Keep changes focused and explain observable behavior and checks. Tests and examples must use synthetic data; do not attach account tokens, real conversations or provider keys.

For model-selection changes, freeze reference cases and acceptance criteria before calls. Keep failures, timeouts, unknown billing and amended protocols visible. Distinguish policy agreement from actual coding outcomes. Avoid savings or reliability claims that the evidence does not establish.

Before proposing a change, run unit tests, synthetic-example verification and the public-package checks. Review additions to `public-files.json`; unlisted local files are intentionally excluded. Contributions to the public source are under the MIT license.
